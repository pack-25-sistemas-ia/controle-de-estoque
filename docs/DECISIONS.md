# DECISIONS — Controle de Estoque Inteligente

| ID | Decisão | Motivo |
|---|---|---|
| D-E1 | Layout do Core na raiz (`app/`, `lib/`, `components/`), **sem `src/`** e **sem shadcn**; diretório mantém o slug do catálogo `sistemas/07-controle-de-estoque` (o prompt cita `07-estoque`). A estrutura `features/*` do prompt vira `lib/inventory/*` (domínio e leituras), `lib/inventory/actions/*` (casos de uso) e `components/inventory/*` | `sync-core`, `export-system` e `validate-catalog` dependem do layout/slug; kit de UI do Core é o mesmo dos sistemas 01–06 |
| D-E2 | **Fonte de verdade = livro de movimentos** (`stock_movements`, só-acréscimo); `inventory_balances` e `inventory_cost_state` são derivados, escritos só pelas funções `inv_*` na mesma transação; função de reconciliação `inv_reconcile` e testes provam que fecham | Prompt §7; nenhum campo de saldo editável |
| D-E3 | Regras críticas no banco (funções SQL SECURITY DEFINER + constraints + gatilhos), com testes SQL, concorrência real e mutação; TS só espelha para pré-visualização | Mesmo padrão validado nos sistemas 01–06 |
| D-E4 | Depósitos são a unidade de saldo; localizações internas são cadastro hierárquico simples sem saldo próprio (sem WMS) | Prompt §6.9/§12 permite começar só com depósitos |
| D-E5 | Operações nascem **confirmadas** numa única chamada atômica (sem rascunho de movimentação). Único fluxo com aprovação: inventário físico (aguardando aprovação) | Evita estados intermediários que quebram a conservação; alertas «aguardando confirmação» referem-se a inventários |
| D-E6 | Quantidade `numeric(18,3)`, escala por unidade (0–3); dinheiro em centavos `bigint`; valor acumulado do estoque em centavos inteiros (a média é derivada); arredondamento meio-para-o-par; `decimal.js` só no TypeScript para exibição | Sem float; conservação até o último centavo (COSTING_RULES.md) |
| D-E7 | Importação **somente CSV** (leitor próprio estrito, testado, sem dependência) e exportação CSV com neutralização de fórmulas. ExcelJS/SheetJS descartados (manutenção, peso, segurança); XLSX/PDF ficam como limite documentado. Papa Parse avaliado e dispensado por redundância | Menos superfície de ataque e de memória em serverless |
| D-E8 | Custo médio ponderado móvel **por produto na organização**; transferência não muda o valor consolidado; valor por depósito = distribuição proporcional por maior resto | Prompt §17; soma dos depósitos fecha exatamente com o total |
| D-E9 | Estoque negativo **bloqueado sempre** (check no banco), sem configuração para liberar | Prompt §28 |
| D-E10 | Reservas fora do MVP: `quantity_reserved` com `check = 0`; interface não sugere reserva; disponível = físico | Prompt §7.3 |
| D-E11 | Papéis do Core → perfis: owner/admin = Administrador; manager = Gestor de estoque; member = Operador; viewer = Consulta. Operador pode ter **depósitos autorizados** (`warehouse_access`); sem linhas, acessa todos | Prompt §5/§12; ver PERMISSIONS.md |
| D-E12 | Leitura de código: digitar/colar/leitor USB é o caminho principal; câmera é opcional (`BarcodeDetector` nativo, ZXing sob demanda), só após clique; `Permissions-Policy: camera=(self)` | Prompt §21; câmera nunca é pré-requisito |
| D-E13 | Fonte do prompt: o texto colado no chat é truncado (limite de 50 mil caracteres) e termina na seção 31 (skills). Seções posteriores (testes, critérios de aceite, fases, relatório, ordem de execução) **não foram recebidas**; o plano usa as fases análogas do Sistema 06 até o Word completo ser disponibilizado | Honestidade sobre a fonte; ajustar o plano ao texto íntegro quando chegar |
| D-E14 | O número da operação vem de uma **sequência global** (`inv_op_seq`), sem contador por empresa; a numeração «nº 1, 2, 3…» de cada empresa é calculada na visão `inv_operations_view` por `row_number` | A rodada de concorrência/mutação mostrou que um contador por empresa (uma linha atualizada em toda operação) serializava todas as operações da empresa — linha quente. Sequência não trava e continua sem repetir números |
| D-E15 | Anexos de imagem de produto são servidos por `/api/attachments/ID?inline=1` (URL assinada curta, redirecionamento), nunca por URL pública; etiquetas de código de barras são desenhadas em `canvas` | CSP com `img-src 'self'` e sem estilo em linha (SVG de JsBarcode usa `style`) |
| D-E16 | Rotinas de reposição/avisos rodam por pessoa autenticada (painel ou botão), sem agendador com privilégio | Nenhuma função executa «como administrador» sem identidade; idempotência torna a repetição segura |
